# 鱼鱼的耳朵（dsh-hear）

给 DSH 里跑着的 agent 装一对耳朵：**整段波形直接交给会听音频的模型**，让它听完描述听感，插件再自己算基频、能量、频谱重心和停顿，两边对得上才算数。

不是把声音转成文字再读——那不算听。

[下载 v0.1.0](https://github.com/FlyingCharon/dsh-hear/releases/tag/v0.1.0) · [安装](#安装) · [已知问题](#已知问题)

## 一、听的定义

- 整段波形直接交给会听音频的模型（默认本地 Qwen2-Audio 7B，4bit），让它听完描述听感；
- 插件自己再算一遍基频、能量、频谱重心、停顿分布，两边对得上才下结论；
- **不做**先把声音转成文字再读文字的事，那不算听。

## 二、一次听什么

- 输入：音频路径 + 想问的问题（可以一次问几条）。
- 输出四块，缺一不可：
  1. 结论（直接回答问的问题）
  2. 它自己补充的听感
  3. 情绪 / 状态变化的时间点
  4. 我自己算的数值（基频、能量、频谱重心、停顿）
- 默认每次落一份记录到 `~/.dsh/hear/records`，可以在选项里关掉。

## 三、多长的音频怎么办

- 20 秒以内：按对话听；
- 20 秒到 1 分钟：拿不准就先问一句「这是你在跟我说话，还是让我听东西」；
- 超过 1 分钟：先问要不要分段，你点头才按 60 秒一段切开听，听完合起来，时间点自动加上每段起点；你说不分就整段听，但会提示可能漏细节。

## 四、QQ 语音

- 可以配多条桥接，一条管一个 QQ 号：各自填自己的语音目录、文件名开头、OneBot 地址、Token、发给谁；
- 每条桥接只听自己目录里的语音，也只回自己那个号；
- 连续发的时候，以最后一条之后静默 9 秒（可调 5~20 秒）为准，凑齐了才处理一次，期间不逐条回；
- 听完的内容会进当前对话的上下文；
- 也可以主动发一条回去：每批最多 0~10 条（0 表示不发），有冷却时间，避免刷屏。

## 五、什么时候启动、什么时候关闭

- 收到音频就自动拉起服务；第一次加载模型约 40 秒，状态会显示「正在启动」；
- 从我回完那句话、这一轮结束时开始倒计时，按选项里的分钟数（默认 5 分钟，1~30 可调）；
- 这期间你再说一句话，倒计时清零，重新从这一轮结束算；
- 手动有「立即启动」「立即关闭」；
- 卸载插件或退出程序时，会把自己启动的那个服务进程收掉。

## 六、显存

- 启动前如果空闲显存不到约 4.5G，会弹窗告诉你剩多少、需要多少；
- 你点确定，才按「显存优先级」去关语音合成（关的是你填的那几个端口，默认 8770、9880）；
- 点取消就什么都不动，不会自己杀进程。

## 七、显存优先级

- 两档：**先关语音合成**、**先关耳朵**，默认先关语音合成；
- 关掉的语音合成要你自己再启动回来（`tts\start_voice.bat`）。

## 八、判断模式

- 自动判断 / 每次都先问 / 一律当对话 / 一律当素材，四选一；
- 判断完会在结果里写一句「当对话听」或「当素材收了」，你可以一句话纠正。

## 九、清理提醒

- 每两天晚上 22:00 提醒一次（时间在配置里），报最近两天的语音文件数、听音记录数、切段临时文件和占用体积；
- 你说清才清，你不说就一条都不动；
- 清的时候会先弹确认框。

## 十、界限

- 只能听，不会生成音乐；
- 不做声纹识别、身份判断这类事；
- 听感是模型的主观描述，不等于人耳，也不保证准确；
- 各模型许可证不一样，商用前自己看一遍。

## 十一、模型

- 本地可选八个，现在只有 Qwen2-Audio-7B 的推理是内置接通的，其余模型能下载、能体检，但还听不了；
- 也可以走云端（Gemini / GPT-4o / 通义 Qwen-Omni），不占显存，但要网、要 API Key、按量收费；
- 模型不随插件分发，在「模型」页单独下载，可以取消、可以卸载。

## 系统要求

- Windows 10 / 11（服务脚本用了 Windows 的进程、端口检测）；
- NVIDIA 显卡，显存 6G 起；默认的 Qwen2-Audio 4bit 约占 4.5G，加载前插件会先查剩余显存；
- 磁盘：模型 16.8G，Python 依赖另有几 G；
- Python 3.10 或 3.11（3.12 有些包还没轮子）；
- 第一次启动要联网下模型。

## 安装

1. 装 Python 3.10 / 3.11，装完 `python --version` 能看到版本；
2. 装依赖，一条命令（国内可加 `-i https://pypi.tuna.tsinghua.edu.cn/simple`）：

   ```
   pip install torch torchaudio transformers accelerate soundfile numpy fastapi uvicorn bitsandbytes pysilk
   ```

3. 装插件，两种任选：
   - 从 GitHub：`dsh plugin add git+https://github.com/FlyingCharon/dsh-hear`
   - 或者下 [release 里的 zip](https://github.com/FlyingCharon/dsh-hear/releases/tag/v0.1.0)，解压后在设置里本地安装，选解压出来的目录

   **路径和目录名别带中文**，带中文的安装重启后可能加载不上；
4. 打开 设置 → 鱼鱼的耳朵（有状态 / 选项 / 模型 / 诊断四个页签），首次引导会查显存、硬盘、网络、Python 和依赖，然后给一个推荐模型；
5. 到「模型」页下载 `Qwen2-Audio-7B-Instruct`（16.8G），下完点启动；
6. 状态页显示「已启动」就能听，拿仓库里的 `测试音频/` 那五段先试。

## 已知问题

- **会编具体声源**：7B 4bit 偶尔把咬字的咔哒声说成「掌声」，甚至往上编「表彰活动」。提示词里加了禁令，大部分时候压得住，但不是 100%；
- **细情绪判错**：「平静」和「悲伤」这种差别它分不清，靠提示词救回一部分；
- **含糊的短音频判断不稳**：三五秒、又没点名的那种，判成对话还是素材不一定对；
- **只有 Qwen2-Audio 真跑通**：Qwen2.5-Omni、MiniCPM-o 的代码写了但没实测；GLM-4-Voice、Step-Audio-2-mini、Kimi-Audio 只能下载和体检，还不能听；
- **时间点**：模型自己写的秒数可能超过音频长度，插件会把越界的丢掉，偶尔留下半句；
- **语音回复**：要每条桥填自己的 OneBot 地址、Token 和发给谁，没填就发不出去；选项页有「试发」可以先验；
- **桥接共用一个目录**：文件名里没有账号信息，两条桥盯同一个目录和前缀时，只有第一条收得到，插件会提示冲突；
- **中文路径**：模型目录、缓存目录别带中文；
- **老黄卡**（10 系及更早）不支持 bf16。

## 服务

- 插件自带 `server/hear_server.py`，默认端口 8779，环境变量 `QWEN_AUDIO_PORT` 可改；
- 端口被别的程序占用时，启动会自动换一个空端口，并把新端口写回配置；要是占着的是上次没退干净的自己，会先问你要不要结束它；
- 也可以点「一键对齐端口」先查。

## 配置与数据

- 配置：`~/.dsh/hear/config.json`（不走 cordis.patch.yml；里面有 Token 和 API Key，别外发）
- 听音记录：`~/.dsh/hear/records`
- 错误日志：`~/.dsh/hear/errors.jsonl`（同一种错误十分钟内只记一次）
- 待处理语音：`~/.dsh/hear/qq-pending.json`
- 诊断快照：`~/.dsh/hear/diagnose`
- 服务日志：`~/.dsh/hear/service.log`

## 已知的坑

- QQ 语音是 silk 格式，没装 `pysilk` 听不了；
- Windows 上 `bitsandbytes` 装 4bit 要配对 CUDA 版本；
- 中文路径容易出问题：模型目录、缓存目录都别带中文；
- 老黄卡（10 系及更早）不支持 bf16；
- 别的桥接如果不用 `media_` 开头命名，就在「文件名开头」里改成它用的前缀，填 `*` 表示这个目录里所有音频都算。
